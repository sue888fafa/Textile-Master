# 绣线工坊 Godot 版

这是一个独立的 Godot 4.x 原生 2D 版本。打开本目录中的 `project.godot`，运行 `main.tscn` 即可开始游戏。

玩法逻辑位于 `scripts/main.gd`，包括：

- 9:16 竖屏画布与闭环传送带；纺织机不再固定在地图上，而是在连连看配对成功后从起点进入传送带。
- 九种颜色、持续射线绣制；不再有订单波次、颜色订单限制或动态机器数量上限，连连看中任意有效颜色配对成功即可生成线团。有效颜色顺序为珊瑚红、橙色、向日黄、橄榄绿、叶绿色、湖蓝色、深蓝色、紫色、粉色。
- 下方区域改为连连看棋盘，使用共享的 `10×25` 网格；默认 36 种图标按 9 个颜色组排列。每个编制目标随机生成一对同样式图标，同色但不同样式不能配对。
- 连连看允许从棋盘外边界绕行；配对失败、颜色不同或路径被挡住时不会消耗线团。
- 配对成功后生成对应颜色的线团，先从棋盘位置移动到传送带左上角起点，再生成动态纺织机进入传送带。纺织机只会寻找同颜色的编制目标，不会把产物纺织到其他颜色的格子。
- 动态纺织机可同时运行多台，经过对应颜色有效点位最近的传送带位置时进入持续纺织状态。纺织线会从机器当前位置连接到目标方块，并随机器移动改变长度；线头在目标方块内从左到右、从上到下完成 5 条扫描，方块会逐步显示已纺织效果。完成后机器继续运行到终点消失。
- 连连看配对成功后先播放连线特效，特效结束才移除物品并生成线团。游戏不显示订单气泡，也不按波次限制配对。
- 布局编辑器中的点位必须严格等于编制目标数的两倍；所有生成的图标都属于有效纺织物品，不再生成干扰方块。
- 有效针脚由连连看产物生成，低亮度点位为本局装饰点，不计入胜利条件。
- 鼠标、触摸点击和 `R` 键重新开始。
- 游戏暂停后可以点击“选择关卡”，从当前已配置的关卡列表中直接切换并开始；再次点击右上角暂停按钮可返回暂停主界面。

美术替换入口在主场景 Inspector 的 `Art Slots` 分类。可以替换背景、顶部 HUD、编制棋盘、连连看公共底图和默认 36 个独立物品图标、传送带、纺织机左/底/右方向资源、9 种毛线球和 9 种已纺织块；三个道具栏也拆分为公共底图和三个独立道具图标。没有填入的资源会继续使用脚本绘制的占位样式。具体顺序见 `assets/README.md`。

顶部 HUD 和底部道具栏已经作为 `Main/UI` 下的场景节点提供：`ScoreUI`（金币）、`LevelUI`（关卡）、`PauseUI`（暂停）、`AddTimeUI`（增时）、`ShuffleUI`（打乱）、`AutoClearUI`（自动消除）。在 2D 场景中选中节点后，可以直接拖动节点改变位置，也可以在 Inspector 修改 Control 的 `Size` 或 `Scale`；运行时绘制的内容会读取节点的实际位置和尺寸。三个道具的图片可在 Main Inspector 的 `Art Slots` 中分别替换 `add_time_texture`、`shuffle_texture` 和 `auto_clear_texture`。节点只负责布局控制，游戏输入仍由 Main 统一处理；如果删除节点，对应元素会回退到 `score_rect`、`level_rect`、`pause_rect` 或默认道具栏位置。

布局替换入口在同一个节点 Inspector 的 `Layout - 390x844` 分类。正式关卡使用 `Shared Game Grid` 的 `layout_grid_size`、`game_grid_layout`、`stitch_requirement_layout`、`belt_grid_position` 和 `belt_grid_size`；每个关卡资源独立保存这些字段。`belt_path_points` 仅保留给未配置共享网格的旧场景。`传送带对象尺寸` 分类中的 `dynamic_machine_size` 控制机器图片大小，`conveyor_product_yarn_radius` 控制移动到传送带起点的线球大小，`machine_yarn_radius` 控制机器内部线球大小。新传送带资源位于 `assets/conveyor.png`，运行时会根据共享网格中的传送带矩形自动生成闭环路径。

编制区域现在还有一个可直接在 2D 场景中编辑的 `StitchAreaUI` 子节点。选中 `Main/StitchAreaUI` 后，可以在 2D 视图中拖动它的位置，或使用 Control 的边界手柄调整宽高；也可以在 Inspector 修改 `Position`、`Size` 或 `Scale`。运行时会读取这个节点的实际矩形，编制图案、编制动画、纺织线和胜利图案展示都会同步使用该位置和大小。删除该节点时才回退到 Main 的 `board_layout_rect`。

关卡图形编辑入口在 `Main` 节点 Inspector 的“布局编辑器”和“编制区域编辑器”。正式关卡使用 `layout_grid_size`（默认 `Vector2i(10, 25)`）和 `game_grid_layout` 保存共享布局中的连连看物品；传送带由 `belt_grid_position`、`belt_grid_size` 作为一个整体单位保存。编制图案使用独立的 `pattern_grid_size`、`pattern_layout` 和 `stitch_requirement_layout` 保存，不会占用共享布局中的连连看格子。编制区域的位置和大小推荐直接编辑 2D 场景树中的 `Main/StitchAreaUI` 节点；`board_layout_rect` 仅作为没有该节点时的回退配置。

项目还提供了可视化的 `Cross-Stitch Pattern Editor` 插件。打开 `main.tscn` 并在场景树中选中 `Main`，Godot 右侧会显示“布局编辑器”和“编制区域编辑器”两个面板。布局编辑器用于摆放连连看物品和拖动传送带；编制区域编辑器单独用于摆放编制颜色和绑定需求物品。点击各面板的应用按钮后，再按 `Ctrl+S` 保存场景，应用操作支持 Godot 撤销/重做。

面板顶部的关卡工具可以新增、复制、切换、上移、下移和移出多个关卡。正式关卡保存在 `levels/level_001.tres` 这类独立资源文件中，`Main` 的 `level_files` 只保存文件路径和游玩顺序；`start_level_index` 可以设置开局关卡序号（从 0 开始）。

布局编辑器中的“保存当前关卡”会把当前配置写入选中的 `.tres` 文件；编制区域编辑器中的应用按钮也会同步保存该文件。调整顺序后按 `Ctrl+S` 保存 `main.tscn`。点击“移出”只会从游玩顺序中移除文件，不会删除磁盘文件；点击“从文件恢复”可以扫描 `levels/` 并重新加入被移出的关卡。复制关卡会创建独立副本，之后修改副本不会影响原关卡。旧版场景若仍把关卡内嵌在 `main.tscn`，可点击“迁移内嵌关卡”一次性导出为独立 `.tres` 文件。

例如在编制区域编辑器中选择颜色工具，或在 `pattern_layout` 中编辑以下内容：

```text
..cc.....
.cggc....
cggggc...
.cggc....
..cc.....
.........
.........
.........
.........
```

保存场景后，运行时会使用同一份配置。脚本使用 `@tool`，因此修改共享网格或关卡后，Godot 编辑器画布会自动刷新预览；编制块所在格不会生成连连看物品。空图案也是合法配置，运行时会安全显示为完成状态。

连连看棋盘使用共享的 `10×25` 正方形网格；正式关卡会严格保留布局编辑器中的点位位置。每个编制点位自动对应两个同颜色组物品，运行时会随机选择该颜色组中的一个图标样式并分配到这两个点位。动态纺织机可同时运行多台；产品到达起点后创建机器并进入传送带。顶部绣制进度计数已移除，界面已重新上移并扩高下方游戏区以适配 390x844 竖屏。

连连看资源可直接在 `Main` 节点 Inspector 的 `Art Slots` 分类中配置：`link_tile_background_texture` 是所有格子共用的底图，`link_tile_textures` 按颜色组顺序保存图标，`link_tile_style_counts` 保存 9 个颜色组各自启用的样式数（默认每组 4 个，共 36 个槽位，也可以按样式数继续增加数组槽位）。例如样式 `0-3` 属于珊瑚红组，`4-7` 属于橙色组；同一样式才能配对，同色但不同样式不能配对。缺少纹理的槽位使用程序化回退图标。每个编制目标自动生成一对同样式图标，布局编辑器只负责手动摆放这些点位，点位总数必须等于编制目标数的两倍。所有配对成功都会生成线团、纺织机和纺织任务。

编制区域编辑器是物品数量来源：每放置 1 个编制点位，就需要 2 个连连看点位。布局编辑器手动放置的点位只决定位置；运行时按目标颜色组随机分配具体图标样式。例如 5 个红色目标需要 10 个点位，运行时会生成 5 对同样式的红色组图标。

### 统一正方形游戏网格

编辑器现在使用一张共享游戏网格，默认是 `10列 × 25行`。每个单元按 `min(390/列数, 844/行数)` 计算为正方形；在默认边距下单元边长约为 32.8。HUD 不参与吸附，传送带和连连看物品都在同一套网格坐标中编辑；编制方块由独立工具管理。

在 `Main` Inspector 的 `Shared Game Grid` 分类中，`game_grid_layout` 只描述共享布局中的连连看点位：`0` 表示点位，`.` 表示空格；传送带由 `belt_grid_position` 和 `belt_grid_size` 作为一个整体单位占用格子。编制区域内部的图案不写入这份布局，而是在“编制区域编辑器”中单独编辑。

打开场景并选中 `Main` 后，右侧会显示“布局编辑器”和“编制区域编辑器”。布局编辑器中只提供一个小型通用点位图标，点击共享网格即可放置连连看点位；拖动已有点位或蓝色传送带区域会自动吸附到整数网格。传送带尺寸最小为 `5×5`，且不能覆盖连连看点位。编制区域编辑器单独设置图案尺寸和颜色块。

两个编辑器分别校验自己的配置：布局编辑器检查手动连连看点位数量严格等于编制目标数量的两倍、传送带边界和传送带占用冲突；编制区域编辑器检查颜色和可用空间。布局编辑器会实时显示编制目标、所需点位、当前点位和数量状态。分别点击应用后，再按 `Ctrl+S` 保存场景。多关卡模式下，每个关卡独立保存连连看点位布局、编制图案和传送带位置/尺寸。共享网格中的空布局仍是合法配置，但空编制图案不能放置点位。

旧版独立字段仍保留在资源内部用于场景兼容加载，但不会触发旧版随机物品生成；新关卡统一使用 `Shared Game Grid` 的布局文本。`link_cell_gap_ratio` 默认是 `0.02`，表示相邻物品之间只保留约为格子边长 2% 的总间距。`Art Slots` 下的 `link_tile_textures` 可以逐项替换物品图标。

点击“应用到 Main”前插件会校验：手动点位数量必须等于编制目标数量的两倍，传送带不能越界或覆盖点位。物品类型和颜色组由编制区域自动计算，不需要手动绑定具体物品键。

### 统一网格中的传送带

统一网格默认是 `10×25`，坐标从左上角开始，`(0, 0)` 表示第一列第一行。传送带尺寸至少为 `5×5`，可以输入 `5×5`、`8×8`、`10×10` 等尺寸；拖动传送带时位置会自动吸附到整数网格。传送带只能放在共享网格的空格区域，不能覆盖连连看物品。

运行时会根据传送带矩形自动生成带内边距的矩形闭环路径：起点在左上角，终点在左侧起点下方，纺织机方向资源、目标路径和离场位置会随传送带区域自动适配。布局网格中的传送带矩形作为整体占用单位，不会生成连连看物品；编制图案则从当前关卡的独立图案配置绘制在传送带内部。

关卡胜利后，完整的已编制图案会从中央编制区域浮起并移动到胜利 UI 中。动画约 0.9 秒，结束后才显示下方的操作按钮；按钮和图案展示区域可以在 Main Inspector 的“胜利 UI”分组中通过 `victory_panel_rect`、`victory_pattern_rect` 和 `result_action_rect` 调整。还有后续关卡时按钮显示“下一关”，最后一关显示“再玩一次”。
